# SE-4 Quasar Candle Client Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Read candles from `GET /v1/candles` of a running Quasar as exact `Decimal` domain `Candle` objects, over any window, with every failure a distinct typed outcome and never an empty result in place of a failure.

**Architecture:** A small `infrastructure/quasar` package. A strict decoder turns a response body into a `CandlePage` (candles, `next`, retained `coverage` and `series` bounds) or into a typed error; a stdlib `urllib` client fetches one page under a per-operation timeout and a deadline on the body transfer, and a second method pages by `next` and chunks a window into at most 10 000 slots. The client returns what Quasar stores. Successful paging is **not** a consistent snapshot, and the client establishes no availability and no completeness (contract section 3, DR-06, DR-21, OD-6, OD-24): its output is not a snapshot and must not reach a strategy directly (SE-5 does that).

**Tech Stack:** Python 3.12 standard library only (`urllib.request`, `json`, `re`, `time`, `http.client`, `decimal`, `dataclasses`), pytest with a small local stub HTTP server (`http.server`), ruff, mypy strict, import-linter. No new dependency, no new import-linter allowlist entry (`infrastructure` is not default-deny).

**Spec:** `docs/superpowers/specs/2026-11-09-engine-roadmap-design.md` (SE-4). Data contract: `../quasar-market-data/docs/contracts/api-v1.md` sections 0 to 5 (sections 1 Conventions, 2 Errors, 3 Pagination and 5 `GET /v1/candles` are normative for this slice, read 2026-11-10). Rules: `docs/domain.md` DR-11, DR-15, DR-18, DR-19; DR-06, DR-21, OD-3, OD-6, OD-7 and OD-24 stay open and are not decided here.

## Global Constraints

- Layers: `application → strategies | infrastructure → domain`. All new production code is in `src/sentaris_engine/infrastructure/quasar/` and imports only from `domain` (`domain.market.Candle`, `domain.timing.require_instant`) and the standard library. Never import `quasar_market_data`; reach Quasar over HTTP only (DR-18). If `make imports` fails, stop and ask; never widen a contract.
- No runtime dependency. HTTP is `urllib.request` (the roadmap's choice); the stub server in tests is `http.server`.
- **Scope is `GET /v1/candles` only.** No `/v1/coverage`, `/v1/instruments`, open interest, funding, indicators, snapshot building, availability filtering, validation against thresholds, retries, caching, `application` code, strategy, or mapping of errors to evaluation-failure codes (that taxonomy is OD-3, with SE-5 and SE-6) (CLAUDE.md, `docs/domain.md` section 2).
- **What the client claims.** It returns stored rows as Quasar states them. It does not claim a snapshot, consistency across pages, availability at any `as_of`, freshness or completeness. `conflicted` and `coverage` are carried as stated and never interpreted (OD-7, DR-21). No type or field in this package is named `snapshot`, `complete`, `consistent`, `available` or `validated`.
- Prices and volumes are `Decimal` built from the response text, never from a number and never via `float` (DR-11). Contract section 1 "Decimals": a JSON **string** of digits and at most one `.`, no sign, no exponent, no leading zero except `0.x`, no trailing fractional zero. The decoder accepts exactly `(0|[1-9][0-9]*)(\.[0-9]*[1-9])?` by `re.fullmatch` with `[0-9]`, never `\d` (my call: fail closed on anything the contract says is never sent). A number, `bool`, `null` (except `turnover`) or other type is rejected.
- `turnover` is `null` or a decimal string; an **absent** `turnover` key is a violation, never defaulted (DR-15). `conflicted` is exact `bool`.
- Gaps stay gaps: nothing is filled, interpolated or deduplicated (DR-15).
- Contract section 1 "Compatibility": unknown response fields are ignored (at every level, an unknown float included); a **missing** documented field or a wrong type in a JSON object that is otherwise a page is a `ContractViolationError`.
- Limits (contract section 5.1): `limit` 1 to 1000, always sent explicitly, default 1000 (`MAX_PAGE_LIMIT = 1000`); a window of at most 10 000 slots (`MAX_WINDOW_SLOTS = 10_000`). The only served timeframe is `5m` (contract section 5.1): `TIMEFRAME_MS: Mapping[str, int] = {"5m": 300_000}`; an unknown timeframe is a `ValueError` before any request (my call: chunking needs the slot length).
- Paging (contract section 3): time-based. The client always sends an explicit `end`, checks that the echoed `start` and `end` equal what it sent, and continues with `next` as `start` and the same `end`. A returned candle must satisfy `start <= open_time_ms < end`, be aligned to the timeframe and strictly ascend. `next` must be `null` or aligned, strictly greater than the last returned `open_time_ms` and less than `end` (so never returned with an empty `candles`), and a non-`null` `next` requires `len(candles) == limit` (contract section 3: `next` is the first stored candle **not returned** and the server reads `limit + 1` rows); otherwise `ContractViolationError`. That guarantees progress and at most 10 pages per 10 000-slot chunk, so a paging loop always terminates quickly. **This is the whole of what paging promises:** the pages are separate reads at separate moments (contract section 3), and nothing here detects or repairs a change between them (OD-24).
- `coverage` is retained as stated and not interpreted, but it must be consistent with the request and with itself (contract section 5.3), otherwise `ContractViolationError`: `span.start == start`, `span.end == next` when `next` is not `null` and `end` otherwise, `slots == (span.end - span.start) / timeframe_ms`, the five state counts are non-negative `int` and sum to `slots`, and `gap_free` is true exactly when `conflicted_slots`, `unavailable_slots`, `missing_slots` and `beyond_stored_slots` are all 0.
- **Error taxonomy.** Every failure is an exception deriving from `QuasarError` (my call; the roadmap's "typed outcome"), in four distinct kinds, none of which is ever empty data (contract section 2: clients treat `503` as "no data"):
  - `QuasarApiError` (subclasses `InvalidParameterError`, `UnknownSeriesError`, `NotReadyError`): Quasar's own documented error. The status is one of `400`, `404`, `405`, `500`, `503` **and** the body is a well-formed contract section 2 error body (`{"error": {"code": str, "message": str, "details": object}}`).
  - `ContractViolationError(message, status)`: a `200` whose body is a strict-JSON **object** that is not a valid page under contract sections 3 and 5 (a missing field, a wrong type, a numeric price, a window or paging rule broken). The response claims to be Quasar's page and is not.
  - `UnexpectedResponseError(message, status, excerpt)`: a response that cannot be attributed to the Quasar API, such as what a proxy, gateway or other infrastructure produces (contract section 2 puts these out of the contract): any status outside `200` and the five above (`3xx`, `502`, `504`, `204`, `201`, …); a documented status without a well-formed error body (a proxy's `503` or `404` HTML page is not `NotReadyError` or `not_found`); a well-formed error body on an undocumented status; a `200` whose body is not a strict-JSON object (empty, not JSON, truncated, invalid UTF-8, `NaN`, duplicate keys, an array, `null`). The classification is by the shape of the response, not a proof of its origin.
  - `QuasarUnavailableError`: no complete response (refused, reset, truncated body, per-operation timeout, deadline exceeded).
  - No retry: `Retry-After` is surfaced as `NotReadyError.retry_after_s`. Which of these an evaluation turns into which failure code is not decided here (OD-3).
- **Transport.** `GET` only, no request body; no redirect is followed (contract section 1: the API never redirects), so a `3xx` is `UnexpectedResponseError`. **Proxies are not touched**: the client uses urllib's default handlers, so the environment's (and the platform's) proxy settings apply exactly as for any other urllib program; nothing in the contract or the roadmap says Quasar must be reached directly, and a deployment may require a proxy (my call; the contract's origin-form rule is met by an ordinary proxy). The query is built with `urllib.parse.urlencode(..., quote_via=urllib.parse.quote, safe="")` so `&`, `+`, `#`, `%`, space and non-ASCII in a symbol are percent-encoded. `HTTPError` derives from `URLError` and `OSError`: the client catches `HTTPError` **first**, and reading any body is inside a `try` that maps a transport failure (`IncompleteRead`, a reset, a timeout) to `QuasarUnavailableError`.
- **Time bounds** (my call; none is in the contract). Two constructor arguments: `timeout_s: float = 10.0`, the limit of each blocking socket operation (connect, each read), and `deadline_s: float = 30.0`, the limit of one HTTP request as far as the client can check it (after `urlopen` returns and around every body read), with `0 < timeout_s <= deadline_s` (else `ValueError`). `deadline_s` is measured with `time.monotonic()` (infrastructure may read a clock; it only decides whether to fail and never reaches a result): the client passes `timeout_s` to `urlopen`, reads the body in chunks of 64 KiB, and checks the deadline before and after every read and after `urlopen` returns; a request that outlives it is `QuasarUnavailableError` and its connection is closed. So a server that drips the **body** slowly, or stalls a body read, ends the request within about `deadline_s + timeout_s`. **Not under the deadline:** the response head (status line and headers), which urllib reads inside `urlopen`, bounded only per socket operation by `timeout_s`, so a server dripping the head one byte at a time just under `timeout_s` can hold the call past `deadline_s`; and name resolution (`getaddrinfo` blocks outside the socket timeout, not bounded at all; a literal IP or `localhost` avoids it). The deadline bounds the body transfer, not the head and not DNS. There is **no overall budget across the requests of one `read_candles`**: each request is bounded and the request count is bounded by the window, and a budget for a whole pass belongs to the caller (live scheduling, OD-5; SE-9).
- Instants are exact `int` UTC milliseconds validated with `require_instant` (OD-10); `bool` is not an instant. `require_instant` checks neither range nor alignment (OD-10), so the **client** enforces the Quasar contract's own facts before sending (contract section 1 "Time", section 5.1): `946684800000 <= start <= 4102444800000`, `end <= 4102444800000 + timeframe_ms`, `start` and `end` aligned to the timeframe (`% timeframe_ms == 0`), `start < end`; each is a `ValueError` and sends nothing. This is a fact of the Quasar API, not a decision about time inside the engine, and it keeps `read_candles` from fetching whole chunks before the last one fails with `400`.
- Tests are hermetic: `tests/infrastructure/conftest.py` has an autouse fixture that removes every proxy variable (`http_proxy`, `https_proxy`, `all_proxy`, `no_proxy` and their upper-case forms) and sets `NO_PROXY=*`, so a developer's proxy or the macOS system settings never reach the stub on `127.0.0.1`. Tests that exercise a proxy set their own variables.
- ruff line length 120; mypy strict over `src` and `tests`; annotate everything. A negative test that passes a wrong type goes through `cast(Any, value)`, never a bare `# type: ignore` (`warn_unused_ignores`). `make check` passes at the end of every task. Never weaken a check, contract or test. `live` tests are excluded by default (marker already registered).
- **Docs in the same commit** (CLAUDE.md, `docs/domain.md` sections 9 and 11): each task's commit carries the `docs/domain.md` change that task makes true; the revision 10 row is added in Task 1 and extended by later tasks.
- Commits: one per task, only after the user has agreed that this slice may be committed; each message ends with the executing session's attribution line. Work on a new branch `se-4-quasar-candle-client` created from `main` (my call). The plan itself is committed first as `docs: add SE-4 implementation plan`.

## Review Focus

Input classes the contract implies but the roadmap does not test; each has a named test in the task that owns the code.

1. **A `next` that does not advance** (equal to the last candle, at or past `end`, unaligned, present with no candles, or present on a page that is not full): the loop must raise, never spin, never crawl one candle per request and never silently stop. Tests: Task 1 `test_next_must_advance_inside_the_window`, Task 3 `test_non_advancing_next_ends_in_an_error_after_one_request`.
2. **A response that is not Quasar's page or error** (empty body, truncated JSON, HTML from a proxy, `[]`, `null`, invalid UTF-8, `NaN`, duplicate keys, a proxy's `502`/`503`/`404`, a redirect, a `204`): `UnexpectedResponseError`, never `NotReadyError` or an empty candle list; and a JSON object that is almost a page: `ContractViolationError`. Tests: Task 1 `test_bodies_that_are_not_a_json_object_are_unexpected_responses`, `test_responses_not_attributable_to_the_api_are_unexpected`, Task 2 `test_redirect_is_not_followed`, `test_other_2xx_is_unexpected`.
3. **Hostile or sloppy price text** (`1e5`, `-1`, ` 1`, `1.`, `01`, `0.50`, `NaN`, `Infinity`, `1_000`, non-ASCII digits, a trailing newline, a number instead of a string): rejected, never coerced by `Decimal(...)`, which would accept most of them. Tests: Task 1 `test_numeric_price_is_rejected`, `test_non_canonical_decimal_text_is_rejected`.
4. **A symbol containing `/`, `:`, `&`, `+`, `#`, `%` or non-ASCII** reaches the server unchanged after decoding, and only documented parameters are sent. Test: Task 2 `test_symbol_survives_query_encoding`, `test_fetch_page_sends_only_documented_parameters`.
5. **No complete response** (connection refused, a single stalled read, a server that drips body bytes slowly past the deadline, a reset, a body shorter than its `Content-Length`, in a success or an error body): `QuasarUnavailableError`, never empty data, and in the middle of a multi-page read nothing partial is returned. Tests: Task 2 `test_connection_refused_is_unavailable`, `test_stalled_read_is_unavailable`, `test_slow_body_exceeds_the_deadline`, `test_slow_error_body_exceeds_the_deadline`, `test_truncated_body_is_unavailable`, `test_truncated_error_body_is_unavailable`, Task 3 `test_failure_midway_returns_nothing`.

  - `class NotReadyError(QuasarApiError)`: `reason: str | None` (from `details["reason"]`, `None` when absent or not `str`), `retry_after_s: int | None`; constructor `(status: int, code: str, message: str, details: Mapping[str, object], retry_after_s: int | None)`
- Produces (`...quasar.pages`), all `@dataclass(frozen=True, slots=True)` with no `__post_init__` (only the decoder builds them):
  - `PageRequest(venue: str, symbol: str, timeframe: str, timeframe_ms: int, start: EpochMs, end: EpochMs, limit: int)`
  - `PageCoverage(span_start: EpochMs, span_end: EpochMs, slots: int, present_slots: int, conflicted_slots: int, unavailable_slots: int, missing_slots: int, beyond_stored_slots: int, gap_free: bool)`
  - `CandlePage(start: EpochMs, end: EpochMs, oldest_open_time_ms: EpochMs, newest_open_time_ms: EpochMs, candles: tuple[Candle, ...], next_start: EpochMs | None, coverage: PageCoverage)`
  - `CandleRead(start: EpochMs, end: EpochMs, pages: tuple[CandlePage, ...])` with property `candles -> tuple[Candle, ...]` (the pages' candles in order). Its docstring states: the pages are separate reads taken at separate moments and are **not one snapshot** (contract section 3, OD-24); nothing here detects a change between them; no availability and no completeness is established (DR-06, DR-21, OD-6); `conflicted` and `coverage` are carried as Quasar stated them (OD-7).
- Produces (`...quasar.decoding`):
  - `decode_candle_page(body: bytes, request: PageRequest) -> CandlePage`: a body that is not a strict-JSON object raises `UnexpectedResponseError(status=200)`; an object that is not a valid page raises `ContractViolationError(status=200)`.
  - `decode_error(status: int, body: bytes, retry_after: str | None) -> QuasarError`: **returns** the exception for the client to raise, for **any** non-`200` status. Status in `{400, 404, 405, 500, 503}` and a well-formed error body: `(400, "invalid_parameter")`, `(404, "unknown_series")` and `(503, "not_ready")` give the subclass, any other pair a plain `QuasarApiError`. Everything else, including a `200`, is `UnexpectedResponseError` (excerpt included). `Retry-After` counts only when `re.fullmatch(r"[0-9]{1,6}", value)` (never `$`, which accepts a trailing newline); otherwise `retry_after_s` is `None`.
- Produces (`tests/support/quasar_fixtures.py`, imports nothing from `tests.*`): `candle_json(open_time_ms: int, *, open: str = "82855.4", high: str = "82866.1", low: str = "82768.1", close: str = "82768.2", volume: str = "369.221", turnover: str | None = "30587379.8759", conflicted: bool = False) -> dict[str, object]`; `page_json(request: PageRequest, candles: Sequence[dict[str, object]], *, oldest: int | None = None, newest: int | None = None, next_start: int | None = None) -> dict[str, object]` (echoes the request; the coverage block covers `[start, next_start or end)` with `present_slots` the number of non-conflicted candles, `conflicted_slots` the number flagged, `missing_slots = slots - present - conflicted`, the other two counts 0 and `gap_free` true exactly when those four are 0, so it is always self-consistent and an empty or gapped page reports `gap_free: false`; `oldest` and `newest` default to the first and last candle open time and are **required** when `candles` is empty); `error_body(code: str, message: str = "m", details: Mapping[str, object] | None = None) -> bytes`; `encode(value: object) -> bytes` (`json.dumps(...).encode("utf-8")`); `EXAMPLE_REQUEST` and `EXAMPLE_BODY: bytes`, the contract section 5.2 example verbatim (3 candles from `1792643400000`, `next` `1792644300000`, with `limit=3` in the request).
