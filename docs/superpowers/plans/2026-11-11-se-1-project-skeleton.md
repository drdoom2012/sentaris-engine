# SE-1 Project Skeleton Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. In this project the lifecycle is `/slice SE-1` (`.claude/skills/slice/SKILL.md`); its rules override the sub-skill.

**Goal:** An empty, fully gated Python project for Sentaris Engine: package, tooling, architecture checks with named negative tests, `make check`, CI and the commit hook.

**Architecture:** `uv` project with a `src/sentaris_engine` package of four empty subpackages. Architecture checks are test code under `tests/architecture/`: an AST checker (pure function, in-process tests), import-linter contracts (subprocess tests on a copy in `tmp_path`), and a dependency check over `pyproject.toml` and `uv.lock` (in-process). A shell PreToolUse hook runs `make check` before `git commit` in the committing work tree.

**Tech Stack:** Python 3.12, uv, hatchling, pytest, ruff, mypy (strict), import-linter; POSIX `sh` for the hook; GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-11-se-1-project-skeleton-design.md` (revision 3, approved with A1–A6, H1, H2). Section numbers below ("spec 6.1") refer to it.

## Global Constraints

- Python `3.12` in `.python-version`; `requires-python = ">=3.12"`.
- No runtime dependency. Dev group exactly: `pytest`, `ruff`, `mypy`, `import-linter`. Build backend `hatchling`. No other dependency of any kind; TOML is read with `tomllib`.
- ruff `line-length = 120`; `ruff check` and `ruff format --check` over `src tests`. mypy `strict = true`, `files = ["src", "tests"]`.
- `make check` = `lint typecheck imports test`. Budget: under 60 s with a warm `uv` cache (AC-9).
- No test modifies the working tree, uses the network, the clock or randomness, or runs the real `make check`.
- No change to `docs/domain.md`, `docs/roadmap.md`, `.claude/hooks/agent_dispatch_guard.py`, `.claude/agents/*`, `.claude/skills/*`. `.claude/settings.json` changes only by one appended `PreToolUse` entry (Task 5).
- No production logic: every subpackage holds only a module docstring.
- Rules are cited by ID in comments and docstrings (`DR-08`), never restated.

## Review Focus

1. **macOS and tool debris in `src`** (`.DS_Store`, `__pycache__/`, `py.typed`): the known-child guard must ignore non-code files and caches, or it fails on every developer machine. Test in Task 2.
2. **Negative-test sources in `tests/`** contain banned module names inside string literals: the real-tree scan must not flag strings, only import statements. Test in Task 2.
3. **Hook JSON whose `cwd` contains spaces**, or that has no `cwd`: the hook must quote paths and fall back rather than fail open or crash. Test in Task 5.
4. **Requirement strings in real-world spellings** (`"PyTest >= 9 ; python_version >= '3.12'"`, `"import_linter"`): name extraction must normalise them, or a correct dependency is rejected or a forbidden one slips through. Test in Task 4.
5. **import-linter run that silently checks the real tree** instead of the copy (editable install on `sys.path`): negative cases would pass for the wrong reason. Each case asserts the probe module's name in the output, and the weakening proof shows the case flips. Tests in Task 3.

### Task 2: AST checker and guards (DR-08, DR-18, DR-19 imports)

**Implementer model:** `opus` — import resolution (relative levels, package vs module, `from X import name` semantics) is the core of the DR-08 claim and easy to get subtly wrong.

**Files:**
- Create: `tests/architecture/__init__.py` (empty), `tests/architecture/purity.py`
- Test: `tests/architecture/test_purity.py`

**Interfaces:**
- Produces (in `tests/architecture/purity.py`):
  - `PURE_STDLIB: frozenset[str]` — exactly spec 6.1's list: `__future__ abc collections dataclasses decimal enum functools itertools math operator re types typing`.
  - `FORBIDDEN_CALLS: frozenset[str]` — exactly `open input print breakpoint __import__ eval exec compile globals vars`.
  - `BANNED_EVERYWHERE: frozenset[str]` — `quasar_market_data ccxt binance pybit okx kucoin krakenex coinbase cryptofeed freqtrade hummingbot`.
  - `KNOWN_CHILDREN: frozenset[str]` — `domain application strategies infrastructure`.
  - `find_violations(module: str, *, is_package: bool, source: str) -> list[str]` — one human-readable string per violation; `[]` when clean.
  - `unknown_children(package_dir: Path) -> list[str]` — sorted names of direct children not in `KNOWN_CHILDREN`.
  - `module_name(path: Path, root: Path) -> tuple[str, bool]` — qualified name and `is_package` for a `.py` file under `root` (the directory that contains the top-level package, i.e. `src` or the repo root for `tests`).

**Rules `find_violations` applies** (spec 6.1–6.3; the implementer writes the body):

- Unparseable source → exactly one violation.
- Relative imports in any module (`tests.*` included) resolve against the module's package (`module` itself if `is_package`, else its parent); going above the module's top-level package is a violation.
- Every module: any import whose resolved top-level name is in `BANNED_EVERYWHERE` is a violation. Modules that are not pure (`sentaris_engine.infrastructure.*`, `tests.*`) get only this rule and the two above.
- A module is **pure** if it is `sentaris_engine` or lies under `sentaris_engine.domain`, `.application` or `.strategies`. Only pure modules get the rules below.
- Resolution: as above for relative imports. `import a.b as c` → `a.b`. `from M import n1, n2`: if resolved `M` is `sentaris_engine` or below, each `M.ni` is checked; otherwise `M` is checked. Matching of internal names is by whole dotted components (`sentaris_engine.domainx` is not under `sentaris_engine.domain`).
- Internal names allowed: for `domain` modules, `sentaris_engine.domain` and below; for `application`/`strategies` modules, their own subpackage and below plus `sentaris_engine.domain` and below; for the root, none. Everything else internal (the root itself included) is a violation.
- External names: allowed only if the top-level name is in `PURE_STDLIB`.
- All `ast.Import`/`ast.ImportFrom` nodes anywhere in the tree count (`ast.walk`), including `if TYPE_CHECKING:` (A6).
- `ast.Call` whose `func` is an `ast.Name` in `FORBIDDEN_CALLS` is a violation.
